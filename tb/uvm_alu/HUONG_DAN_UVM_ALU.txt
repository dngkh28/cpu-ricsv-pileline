---------------------------------------------------------------------
BƯỚC 1: alu_if.sv  (INTERFACE)
---------------------------------------------------------------------
Interface gom các dây của DUT thành một cổng. Đây là cầu nối duy nhất
giữa class UVM và module DUT. alu không có clock, nhưng driver và
monitor cần nhịp để lấy mẫu nên ta thêm clk. Thêm "valid": tín hiệu
chỉ dùng cho testbench (KHÔNG nối vào DUT), bằng 1 đúng 1 chu kỳ khi
driver đưa một giao dịch vào; monitor dựa vào đó biết lúc nào có giao
dịch thật.

Code (alu_if.sv):

  interface alu_if(input logic clk);   // clk do top tạo, interface chỉ nhận
    logic [31:0] a, b, result;
    logic [3:0]  alu_control;
    logic        zero;
    logic        valid;                // chỉ dùng cho testbench
  endinterface

Kiểm tra: chưa cần chạy (chưa có top.sv).

BƯỚC 2: alu_pkg.sv + top.sv  (KHUNG + LẦN CHẠY ĐẦU TIÊN)
---------------------------------------------------------------------

      endtask
    endclass

top.sv:

  module top;
    import uvm_pkg::*;
    import alu_pkg::*;

    bit clk = 0;
    always #5 clk = ~clk;                  // clock chu kỳ 10

    alu_if vif(clk);                       // tạo bó dây, đưa clock vào

    // nối DUT vào các dây trong vif
    alu dut(.a(vif.a), .b(vif.b), .alu_control(vif.alu_control),
            .result(vif.result), .zero(vif.zero));

    initial begin
      // đưa vif xuống cho driver và monitor (chuỗi "vif" phải khớp)
      uvm_config_db#(virtual alu_if)::set(null, "*", "vif", vif);
      run_test();   // tên test lấy từ +UVM_TESTNAME (run.sh mặc định alu_test)
    end
  endmodule

---------------------------------------------------------------------
BƯỚC 3: alu_item.sv  (TRANSACTION)
---------------------------------------------------------------------
Một transaction = một phép tính của alu, một gói dữ liệu. Đầu vào
(a, b, alu_control) do sequence tạo. Đầu ra (result, zero) do monitor
điền khi thu lại từ dây.

alu_item.sv:

  class alu_item extends uvm_sequence_item;
    `uvm_object_utils(alu_item)

    bit [31:0] a, b;                       // đầu vào
    bit [3:0]  alu_control;                // đầu vào
    bit [31:0] result;                     // đầu ra, monitor điền
    bit        zero;                       // đầu ra, monitor điền

    function new(string name = "alu_item");
      super.new(name);
    endfunction

    // in item ra dạng dễ đọc trong log
    function string convert2string();
      return $sformatf("op=%b a=%08h b=%08h -> result=%08h zero=%0b",
                       alu_control, a, b, result, zero);
    endfunction
  endclass

Thêm vào alu_pkg.sv (sau dòng include uvm_macros, trước class alu_test):
  `include "alu_item.sv"

Kiểm tra: ./run.sh vẫn phải ra "khung chay duoc", 0 lỗi.

---------------------------------------------------------------------
BƯỚC 4: alu_seq.sv  (SEQUENCE)
---------------------------------------------------------------------
Sequence sinh chuỗi transaction. Vì không có rand/constraint, ràng
buộc viết tay: alu_control chỉ chọn trong danh sách lệnh hợp lệ; 50%
số hạng là giá trị biên (0, 1, 0xFFFFFFFF, 0x80000000) để bắt trường
hợp biên.

alu_seq.sv:

  class alu_seq extends uvm_sequence#(alu_item);
    `uvm_object_utils(alu_seq)

    int n = 200;                           // số phép tính cần sinh

    function new(string name = "alu_seq");
      super.new(name);
    endfunction

    // chọn một số hạng: 50% là giá trị biên, còn lại ngẫu nhiên
    function bit [31:0] pick_operand();
      case ($urandom_range(7, 0))
        0: return 32'h0;
        1: return 32'h1;
        2: return 32'hFFFFFFFF;
        3: return 32'h80000000;
        default: return $urandom;
      endcase
    endfunction

    task body();
      // danh sách alu_control hợp lệ (11 lệnh)
      bit [3:0] ops[11] = '{4'b0000, 4'b0001, 4'b0010, 4'b0100, 4'b1000, 4'b0011,
                            4'b0101, 4'b1010, 4'b0110, 4'b0111, 4'b1001};
      repeat (n) begin
        alu_item it = alu_item::type_id::create("it");
        start_item(it);                    // xin phép gửi item
        it.a           = pick_operand();
        it.b           = pick_operand();
        it.alu_control = ops[$urandom_range(10, 0)];
        finish_item(it);                   // gửi item, chờ driver nhận xong
      end
    endtask
  endclass

Thêm vào alu_pkg.sv:  `include "alu_seq.sv"
Kiểm tra: ./run.sh vẫn chạy được (chưa dùng tới sequence này).

---------------------------------------------------------------------
BƯỚC 5: alu_driver.sv  (DRIVER)
---------------------------------------------------------------------
Driver lấy item từ sequencer rồi gán lên dây của DUT qua interface.
Mỗi item mất 2 chu kỳ: chu kỳ 1 đặt dữ liệu và valid=1; chu kỳ 2 hạ
valid=0. Nhờ đó monitor chỉ thấy đúng 1 lần valid=1 cho mỗi item.

alu_driver.sv:

  class alu_driver extends uvm_driver#(alu_item);
    `uvm_component_utils(alu_driver)

    virtual alu_if vif;                    // tham chiếu tới interface thật

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    // lấy vif từ config_db (top đã set)
    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      if (!uvm_config_db#(virtual alu_if)::get(this, "", "vif", vif))
        `uvm_fatal("DRV", "khong lay duoc vif tu config_db")
    endfunction

    task run_phase(uvm_phase phase);
      vif.valid <= 0;
      forever begin
        seq_item_port.get_next_item(req);  // xin item từ sequencer
        @(posedge vif.clk);
        vif.a           <= req.a;
        vif.b           <= req.b;
        vif.alu_control <= req.alu_control;
        vif.valid       <= 1;              // báo "có giao dịch"
        @(posedge vif.clk);
        vif.valid       <= 0;
        seq_item_port.item_done();         // báo đã xong, xin item kế
      end
    endtask
  endclass

Thêm vào alu_pkg.sv:  `include "alu_driver.sv"

---------------------------------------------------------------------
BƯỚC 6: alu_monitor.sv  (MONITOR)
---------------------------------------------------------------------
Monitor CHỈ quan sát dây, không điều khiển. Khi valid=1 nó thu a, b,
alu_control, result, zero thành một item MỚI và gửi đi bằng analysis
port (ap.write). Item này khác item của driver: nó chứa cả kết quả
thật trên dây, nên scoreboard kiểm tra đúng thứ thực sự xuất hiện.

alu_monitor.sv:

  class alu_monitor extends uvm_monitor;
    `uvm_component_utils(alu_monitor)

    virtual alu_if vif;
    uvm_analysis_port#(alu_item) ap;       // cổng gửi item đi

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      ap = new("ap", this);
      if (!uvm_config_db#(virtual alu_if)::get(this, "", "vif", vif))
        `uvm_fatal("MON", "khong lay duoc vif tu config_db")
    endfunction

    task run_phase(uvm_phase phase);
      alu_item it;
      forever begin
        @(posedge vif.clk);
        if (vif.valid === 1'b1) begin      // có giao dịch thật
          it = alu_item::type_id::create("mon_it");
          it.a           = vif.a;
          it.b           = vif.b;
          it.alu_control = vif.alu_control;
          it.result      = vif.result;
          it.zero        = vif.zero;
          ap.write(it);                    // gửi cho scoreboard
        end
      end
    endtask
  endclass

Thêm vào alu_pkg.sv:  `include "alu_monitor.sv"

---------------------------------------------------------------------
BƯỚC 7: alu_scoreboard.sv  (SCOREBOARD)
---------------------------------------------------------------------
Scoreboard nhận item từ monitor, tính kết quả đúng bằng mô hình tham
chiếu rồi so với DUT. Mô hình phải viết ĐỘC LẬP với RTL (theo đặc tả
RISC-V); nếu chép logic từ alu.v thì lỗi sẽ lặp lại ở cả hai bên và
không bị phát hiện. Coverage đếm bằng tay: op_seen (mỗi alu_control đã
gặp chưa), số lần result=0, số lần tràn.

alu_scoreboard.sv:

  class alu_scoreboard extends uvm_scoreboard;
    `uvm_component_utils(alu_scoreboard)

    uvm_analysis_imp#(alu_item, alu_scoreboard) imp;   // cổng nhận item

    int pass, fail;
    int op_seen[bit [3:0]];                // số lần mỗi alu_control xuất hiện
    int n_zero_result;                     // số lần result = 0
    int n_overflow;                        // số lần cộng/trừ bị tràn 32 bit

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      imp = new("imp", this);
    endfunction

    // mô hình tham chiếu: tính kết quả đúng theo đặc tả
    function bit [31:0] ref_model(alu_item t);
      case (t.alu_control)
        4'b0000: return t.a & t.b;                                    // AND
        4'b0001: return t.a | t.b;                                    // OR
        4'b0010: return t.a + t.b;                                    // ADD
        4'b0100: return t.a - t.b;                                    // SUB
        4'b1000: return (t.a < t.b) ? 32'd1 : 32'd0;                  // SLTU
        4'b0011: return t.a << t.b[4:0];                              // SLL
        4'b0101: return t.a >> t.b[4:0];                              // SRL
        4'b1010: return $signed(t.a) >>> t.b[4:0];                    // SRA
        4'b0110: return ($signed(t.a) < $signed(t.b)) ? 32'd1 : 32'd0;// SLT
        4'b0111: return t.a ^ t.b;                                    // XOR
        4'b1001: return t.b;                                          // PASS_B
        default: return 32'd0;
      endcase
    endfunction

    // monitor gọi ap.write -> hàm write này chạy
    function void write(alu_item t);
      bit [31:0] exp_result = ref_model(t);
      bit        exp_zero   = (exp_result == 32'd0);
      bit [32:0] wide;

      // đếm coverage bằng tay
      if (!op_seen.exists(t.alu_control)) op_seen[t.alu_control] = 0;
      op_seen[t.alu_control]++;
      if (exp_result == 0) n_zero_result++;
      if (t.alu_control == 4'b0010) begin
        wide = {1'b0, t.a} + {1'b0, t.b};
        if (wide[32]) n_overflow++;
      end
      if (t.alu_control == 4'b0100 && t.a < t.b) n_overflow++;

      // so sánh DUT với mô hình
      if (t.result === exp_result && t.zero === exp_zero) begin
        pass++;
      end else begin
        fail++;
        `uvm_error("SB", $sformatf("SAI: %s | mong doi result=%08h zero=%0b",
                                   t.convert2string(), exp_result, exp_zero))
      end
    endfunction

    // báo lỗi nếu không nhận được giao dịch nào (testbench hỏng)
    function void check_phase(uvm_phase phase);
      if (pass + fail == 0)
        `uvm_error("SB", "scoreboard khong nhan duoc giao dich nao")
    endfunction

    // in kết quả cuối cùng
    function void report_phase(uvm_phase phase);
      `uvm_info("SB", $sformatf("pass=%0d fail=%0d | alu_control da gap=%0d/11 | result=0: %0d lan | tran/muon: %0d lan",
                pass, fail, op_seen.size(), n_zero_result, n_overflow), UVM_LOW)
      if (fail == 0 && pass > 0) `uvm_info("SB", "*** TEST PASSED ***", UVM_NONE)
      else                       `uvm_info("SB", "*** TEST FAILED ***", UVM_NONE)
    endfunction
  endclass

Thêm vào alu_pkg.sv:  `include "alu_scoreboard.sv"

BƯỚC 8: alu_agent.sv và alu_env.sv  (GHÉP)
---------------------------------------------------------------------
Agent gộp sequencer + driver + monitor. Env gộp agent + scoreboard và
nối monitor -> scoreboard. Kết nối dùng connect_phase (build_phase chỉ
tạo đối tượng).

alu_agent.sv:

  class alu_agent extends uvm_agent;
    `uvm_component_utils(alu_agent)

    uvm_sequencer#(alu_item) sqr;
    alu_driver  drv;
    alu_monitor mon;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      sqr = uvm_sequencer#(alu_item)::type_id::create("sqr", this);
      drv = alu_driver::type_id::create("drv", this);
      mon = alu_monitor::type_id::create("mon", this);
    endfunction

    function void connect_phase(uvm_phase phase);
      drv.seq_item_port.connect(sqr.seq_item_export);   // driver <- sequencer
    endfunction
  endclass

alu_env.sv:

  class alu_env extends uvm_env;
    `uvm_component_utils(alu_env)

    alu_agent      agt;
    alu_scoreboard sb;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      agt = alu_agent::type_id::create("agt", this);
      sb  = alu_scoreboard::type_id::create("sb", this);
    endfunction

    function void connect_phase(uvm_phase phase);
      agt.mon.ap.connect(sb.imp);                       // monitor -> scoreboard
    endfunction
  endclass

BƯỚC 9: alu_test.sv  (TEST) - LẦN CHẠY ĐẦY ĐỦ
---------------------------------------------------------------------
Test tạo env và chạy sequence. raise_objection / drop_objection giữ
run_phase cho đến khi sequence chạy xong; nếu quên raise_objection, mô
phỏng kết thúc ngay ở thời điểm 0 và không có gì xảy ra.

alu_test.sv:

  class alu_test extends uvm_test;
    `uvm_component_utils(alu_test)

    alu_env env;

    function new(string name, uvm_component parent);
      super.new(name, parent);
    endfunction

    function void build_phase(uvm_phase phase);
      super.build_phase(phase);
      env = alu_env::type_id::create("env", this);
    endfunction

    task run_phase(uvm_phase phase);
      alu_seq seq = alu_seq::type_id::create("seq");
      phase.raise_objection(this);                  // giữ run_phase, chưa cho kết thúc
      seq.n = 500;
      seq.start(env.agt.sqr);                       // chạy sequence trên sequencer
      repeat (3) @(posedge env.agt.drv.vif.clk);    // chờ giao dịch cuối qua monitor
      phase.drop_objection(this);                   // xong, cho phép kết thúc
    endtask
  endclass

---------------------------------------------------------------------
BƯỚC 10: THỬ PHÁ alu ĐỂ XEM SCOREBOARD BẮT LỖI
---------------------------------------------------------------------
Một testbench chỉ đáng tin nếu nó báo FAIL khi DUT sai. Làm trên BẢN
SAO, đừng sửa file ../../rtl/alu.v:

  cp ../../rtl/alu.v alu_bug.v

Mở alu_bug.v, đổi dòng SRL:
  4'b0101 : result = a>>b[4:0];
thành:
  4'b0101 : result = $signed(a)>>>b[4:0];

Rồi biên dịch với alu_bug.v thay cho alu.v:
  $Q/vlib work2
  $Q/vlog -work work2 -sv alu_bug.v alu_if.sv alu_pkg.sv top.sv
  $Q/vsim -c -work work2 top +UVM_TESTNAME=alu_test -do "run -all; quit"
(Q và SALT_LICENSE_SERVER đặt như ở mục 0.)

Kết quả mong đợi: TEST FAILED, khoảng 10-15 dòng "SAI:" với op=0101,
ví dụ a=80000000 -> DUT ra fffffff8 còn mô hình mong đợi 00000008.
Xong thì xóa alu_bug.v và work2.

---------------------------------------------------------------------
TÓM TẮT CÁC KHÁI NIỆM (đối chiếu với file uvm.odt)
---------------------------------------------------------------------
Phase chạy theo thứ tự: build (tạo thành phần) -> connect (nối cổng)
-> run (mô phỏng thật) -> check -> report (in PASS/FAIL).

Transaction chạy trên data flow:
  seq tạo item -> driver lái dây -> DUT tính -> monitor thu item mới
  -> scoreboard so với mô hình tham chiếu.

Khi có Xcelium hoặc license đầy đủ, chỉ đổi 2 chỗ: sinh ngẫu nhiên
